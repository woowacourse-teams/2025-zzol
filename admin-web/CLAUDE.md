# CLAUDE.md

ZZOL 백오피스 SPA. 운영자만 쓰는 내부 도구다.

## `frontend/` 규약을 상속하지 않는다

같은 저장소에 있지만 **다른 앱**이다. `frontend/`의 컨벤션을 여기 적용하지 않는다.

| | `frontend/` | `admin-web/` |
| --- | --- | --- |
| 번들러 | webpack | Vite |
| 스타일 | Emotion (`styled`, `css` prop) | Tailwind v4 (CSS-first `@theme`) |
| 상태 | 자체 훅 + Context | TanStack Query |
| 테스트 | Jest | Vitest |
| 사용자 | 일반 유저 | 관리자 허용목록 |

`frontend/.claude/rules/`의 스타일·컴포넌트 규칙은 Emotion 기준이라 여기서는 맞지 않는다. 브랜치 전략과 git push 안전은 **모노레포 루트**를 따른다.

## 명령어

```bash
npm run dev          # Vite :5173 (포트 고정 — OAuth 승인 원본에 등록돼 있다)
npm run lint         # eslint
npm run type-check   # tsc --noEmit
npm run test         # vitest
npm run build        # tsc -b && vite build
```

로컬은 백엔드 `:8080`이 떠 있어야 한다. Vite 프록시가 `/admin/api`를 넘긴다. 배포(CloudFront)와 같은 모양이라 로컬에서만 되는 CORS 설정이 생기지 않는다.

## 지켜야 할 것

### 1. 지표는 Grafana가 못 보는 것만 담는다

응답시간·에러율·JVM은 Grafana(`status.zzol.site`)가 이미 본다. **두 곳이 다른 숫자를 말하는 순간 양쪽 다 신뢰를 잃는다.** 여기 있는 것은 전부 도메인 조인이거나 우리 DB에만 있는 기록이다.

### 2. 못 세는 것은 화면에 적는다

`SCORE_BOARD` 단계는 메모리에만 있어 퍼널에 없다. 늘 0으로 찍히는 칸을 두면 나머지 숫자까지 못 믿게 된다. **빼는 대신 왜 없는지를 화면에 남긴다** (홈 하단 "이 숫자가 세지 않는 것").

### 3. 조회 실패를 "-"로 두지 않는다

`query.data && (...)` 로만 감싸면 실패했을 때 값 자리에 `-`가 남고, 그건 "오늘 0건"과 똑같이 생겼다. 운영자는 처리할 게 없다고 믿고 화면을 닫는다.

- 표 → `DataTable`에 `error`와 `onRetry`를 넘긴다. 로딩과 빈 상태와 실패를 자기 안에서 그린다
- 그 밖의 데이터 영역 → `<Loaded query={...}>`

화면이 직접 세 갈래 삼항을 쓰지 않는다. 예전에는 `error ? <ErrorState/> : <DataTable/>`로 갈라 썼는데, 그러면 실패했을 때 **표 머리까지 통째로 사라져** 비었을 때와 다른 모양이 됐다.

### 4. 색은 회색과 로고색(`#FD6C6E`) 둘뿐이다

초록·노랑·파랑·별도의 빨강을 두지 않는다. **로고색은 채움과 마크로만 쓰고 글자는 잉크가 진다** — 읽힐 만큼 어둡게 내리면 브랜드가 아니라 에러 빨강으로 읽힌다. 근거와 대비 수치는 `docs/design-tokens.md`.

컴포넌트는 원색(`--point-400`)을 직접 쓰지 않고 역할 별칭(`--accent`, `--attention-mark`)을 쓴다.

### 5. 타이포와 폭은 스케일 밖으로 나가지 않는다

역할별 조합표가 `docs/design-tokens.md`에 있다. 표 밖의 조합을 새로 만들지 않는다. 본문 최대폭은 `AdminLayout`의 `<main>` **한 곳에서만** 정한다.

### 6. 같은 동작에 다른 모양을 쓰지 않는다

새 컴포넌트를 만들기 전에 `src/components/ui/`를 먼저 본다. 세그먼트 컨트롤이 세 화면에 각각 손으로 짜여 있다가 모양이 갈린 적이 있고, 지표 한 칸도 세 화면에 따로 있었다.

되풀이되는 조각은 프리미티브로 못 박아 두었다. 목록과 각각이 못 박은 것은 `docs/design-tokens.md` 11절에 있다.

| 프리미티브 | 쓰는 곳 |
| --- | --- |
| `Tile` `TileGrid` | 지표 한 칸과 그 줄 |
| `MetricRow` | 카드 안 목록의 지표 한 줄 |
| `Meter` | 퍼널, 순위 막대, 처리 대기 |
| `TimelineDot` | 조치 이력, 퍼널 단계 |
| `Legend` `Swatch` | 차트 범례 |
| `Loaded` | 조회 로딩과 실패 |
| `DataTable` | 모든 목록. 선택 행, 키보드 이동, 실패와 빈 상태까지 |
| `ContextPanel` | 목록 옆에서 여는 상세 |
| `lib/labels.ts` | 서버 enum 을 화면 말로 |
| `charts/theme.ts` | 툴팁, 축, 격자 |

### 6-1. 좌우 분할은 화면 안에서 하나뿐이다

두 카드를 나란히 놓을 때 비율은 둘 중 하나다. 같은 급의 질문이면 **반반**, 한쪽이 본문이고 다른 쪽이 곁들이면 **넓은 쪽 2, 좁은 쪽 1**. 줄마다 최적 비율을 따로 찾지 않는다.

한때 홈에서 추이와 오늘은 `2:1`, 퍼널과 조치는 `3:2` 였다. 각 줄만 보면 그럴듯했지만 위아래로 놓고 보면 오른쪽 카드들의 왼쪽 모서리가 어긋났다. 눈에 딱 짚이지는 않는데 화면 전체가 어수선해 보이는 원인이 이런 것이다.

### 6-2. 견줄 값은 타일이 아니라 줄로 쌓는다

`Tile` 넷을 늘어놓으면 넷이 서로 무관한 지표로 읽힌다. 서로 견줘야 하는 값들은 `MetricRow` 로 세로로 쌓아 오른쪽 끝에 정렬한다. 그래야 위아래로 훑으면서 자릿수가 비교된다.

타일은 **성격이 다른 것들을 나란히 놓을 때** 쓴다. 홈 상단의 오늘 지표 넷이 그렇다.

처리 대기 다섯은 한때 타일이었는데 세로 막대 목록으로 바꿨다. 다섯 값이 서로 견줘야 하는 것(어디가 제일 밀렸나)이라 위 규칙에 따르면 줄로 쌓는 쪽이 맞았고, 숫자만으로는 39와 30이 눈으로 구분되지 않아 막대를 붙였다.

### 6-2-1. 눈으로 잡던 것은 `npm run ui-check` 가 잡는다

여백이 남는 카드, 두 줄로 접힌 배지, 서로 붙어 보이는 조각 색. 셋 다 리뷰에서 사람이 매번 짚어 주던 것들이라 검사로 옮겼다. **화면 배치를 고쳤으면 돌린다.**

```bash
ZZOL_ADMIN_TOKEN=... npm run ui-check          # 1440px
ZZOL_ADMIN_TOKEN=... WIDTH=1280 npm run ui-check
```

playwright 는 의존성에 없다(브라우저 바이너리까지 받아야 해서 이 검사를 안 쓰는 사람의 설치까지 무거워진다). `npx playwright install chromium` 이 필요하다. 판단 기준과 예외는 `scripts/ui-check.mjs` 주석에 있다.

### 6-3. 그래프 종류는 데이터의 성격이 고른다

종류를 늘리려고 늘리지 않는다. 같은 "비중"이라도 게임별은 순위 막대고 소셜 제공자는 도넛인 이유가 있다. 자리별 근거는 `docs/design-tokens.md` 12절. **이중 축은 어떤 경우에도 쓰지 않는다.**

### 6-4. 목록 화면에도 그 목록 전체의 모양을 올린다

목록만 있는 화면은 "이 방이 어땠나", "이 사람이 얼마나 썼나"에만 답한다. 운영이 실제로 묻는 것은 그 위에 하나 더 있다. **요즘 방들이 어떤 모양인가, 회원 전체가 어떤 모양인가.** 한 판만 해 보고 안 돌아온 사람이 절반이라는 사실은 목록을 아무리 넘겨도 안 보인다.

그래서 방, 유저, 신고, 검열, 조치 이력 화면은 위가 지표, 아래가 목록이다. 그림의 형태는 데이터의 성격이 고른다(`docs/design-tokens.md` 12절). 순서가 있는 수치 구간은 히스토그램(`Histogram`), 항목이 넷 이하인 구성비는 도넛(`DonutChart`), 그 밖의 목록은 가로 막대(`DistributionBars`), 일자별은 계열이 하나면 꺾은선, 둘이면 나란한 막대(`DailyChart`)다. **막대만 넷을 늘어놓지 않는다.** 가로 막대는 컴포넌트 하나로 통일한다 - 같은 일을 하는 그림이 둘이면 한쪽만 고치는 날이 온다.

구간 경계는 **서버가 정한다.** 화면이 나누면 같은 경계가 두 곳에서 관리된다. 그리고 "완주한 방이 몇 퍼센트"처럼 칸을 더해야 나오는 요약 수는 **서버가 따로 내려보낸다** — 화면이 `label === '1명'`으로 칸을 찾아 더하면 라벨을 한 번 다듬는 순간 숫자가 조용히 0이 된다.

### 7. API 타입은 손으로 유지한다

`src/api/types.ts`는 생성물이 아니다. 백엔드 DTO를 고치면 **같은 PR에서 여기도 고친다.** 안 고치면 화면이 조용히 빈칸을 그린다.

생성(`openapi-typescript`)을 걷어낸 이유는 파일 상단 주석에 있다. 요점은 이 파일의 값어치가 필드 이름이 아니라 "그 숫자가 무엇을 세는가"를 적어 둔 주석이라는 것이다.

### 8. 감사 로그에 남는 것을 의식한다

`/admin/api/**`의 POST·PUT·PATCH·DELETE는 전부 감사 로그에 남는다. 조회는 남기지 않는다 — 목록을 열어본 기록까지 쌓으면 실제 조치가 묻힌다.

기록되는 action은 **매핑 패턴**이지 요청 본문이 아니다. 본문을 남기면 로그인 요청의 구글 ID 토큰이 그대로 저장된다.

## 환경 변수

Vite가 `VITE_*`를 **빌드 시점에 인라인**한다. 런타임 주입이 불가능한 대신, prod 번들에 dev 백엔드 주소가 아예 들어가지 않는다는 보장이 생긴다. 그 제약을 안전장치로 쓰고 있으므로 런타임 설정으로 바꾸지 않는다.

| 변수 | 비고 |
| --- | --- |
| `VITE_GOOGLE_CLIENT_ID` | 비밀이 아니다(브라우저에 그대로 노출). 방어는 승인된 원본·서버측 `aud` 검증·허용목록이 한다 |
| `VITE_API_BASE_URL` | 비우면 상대경로. 로컬은 프록시, 배포는 앞단이 받는다 |
| `VITE_ENV_NAME` | `LOCAL`/`DEV`/`PROD`. 상단 배지에 찍힌다 |

CI는 배포 경로(push)에서 이 값들이 비면 중단한다. 비어도 빌드는 성공하지만 그 번들은 로그인 팝업이 안 뜨거나 API를 자기 자신에게 쏜다.

## 토큰 보관

`localStorage`에 둔다. 메모리에만 두면 새로고침마다 구글 팝업이 다시 떠야 하는데, 백오피스는 표를 보다 새로고침하는 일이 잦다. 수명 1시간, 리프레시 없음. 401을 받으면 토큰을 지우고 로그인 화면으로 돌려보낸다 — **자동 재발급은 하지 않는다**(팝업 차단에 걸린다).

## 화면 구성

라우트가 화면 하나에 하나씩 붙는다. 상세는 라우트가 아니라 **패널**이다.

| 경로 | 화면 | 비고 |
| --- | --- | --- |
| `/` | 홈 | 오늘 지표, 14일 추이, 처리 대기, 처리할 일, 퍼널, 게임별, 소셜 제공자 |
| `/reports` | 신고 | 행을 열면 전문과 처리가 패널에서 |
| `/profanity` | 닉네임 검열 | 대기 목록과 금칙어 사전 |
| `/ip-blocks` | IP 차단 | |
| `/rooms` | 방 | 위는 게임별(이탈 포함), 인원, 소요 시간, 진행 단계 넷을 2x2 로. 아래가 목록 |
| `/users` | 유저 | 위는 가입 추이, 제공자, 참여도, 마지막 참여 분포. 아래가 목록 |
| `/patch-notes` | 패치노트 | |
| `/zzolbot` | ZzolBot | 탭은 `?tab=` |
| `/admins` | 관리자 | |
| `/system` | 시스템 | 옛 주소 `/ops` 는 여기로 보낸다 |
| `/audit-logs` | 조치 이력 | |

지워진 화면이 있고 옛 주소는 전부 살려 두었다(북마크와 바깥 링크 때문이다).

- **방 조회와 유저 조회**는 한때 `/trace` 하나로 합쳤다가 **다시 갈랐다.** 합친 이유는 "이게 방 코드인지 유저 코드인지"를 조사보다 먼저 판단하지 않게 하려는 것이었는데, 표 둘이 세로로 쌓이면서 어느 표를 보고 있는지가 흐려졌고 화면이 3800px이 됐다. 찾는 대상이 방인지 사람인지는 문의를 받은 시점에 이미 정해져 있다. 두 화면은 패널에서 서로 건너뛴다(`?from=room:12`).
- **각각의 상세 화면**은 패널이 됐다. 화면이 통째로 바뀌면 돌아왔을 때 검색어와 페이지가 초기화된다.
- **서비스 분석**은 홈이 흡수했다. 홈이 요약을 맡으면서 추이와 퍼널과 게임별 플레이가 두 화면에 같은 모양으로 남았고, 같은 카드가 두 곳에 있으면 한쪽만 고치는 날이 온다.

## 화면에 영문 enum 을 찍지 않는다

서버가 주는 값은 `BUG`, `FLAGGED`, `PLAYING`, `google` 같은 enum 이다. 그대로 찍으면 한글 화면 한가운데 대문자 영문이 서서 그 열만 다른 시스템에서 온 것처럼 보인다.

`lib/labels.ts` 가 번역표를 갖는다. **모르는 값은 원문 그대로 내보낸다** - 빈 칸이나 "기타" 로 바꾸면 서버에 새 값이 생긴 것을 화면에서 알아챌 방법이 사라진다.

감사 로그의 조치도 여기 있다. 서버가 남기는 것은 요청 본문이 아니라 매핑 패턴(`POST /admin/api/reports/{id}/resolve`)이라, 번역하지 않으면 조치 이력이 사람이 읽는 기록이 아니라 서버 로그가 된다.
