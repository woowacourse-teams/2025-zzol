# 디자인 토큰

구현은 [`src/styles/tokens.css`](../src/styles/tokens.css)에 있다. 이 문서는 토큰의 역할과 사용 규칙을 적는다.

## 1. 팔레트

유채색은 서비스 화면의 팔레트를 그대로 쓴다. `frontend/src/styles/theme.ts`의 `color.point`와 브랜드 스케일 50~500이다. 로고 워드마크 색 `#FD6C6E`는 `point-400`과 같은 값이다.

회색은 서비스의 `color.gray` 대신 자체 쿨 그레이 스케일을 쓴다. 밝기 단계는 서비스와 같다.

## 2. 로고색은 글자에 쓰지 않는다

로고색은 채움과 마크로만 쓰고, 글자는 잉크가 진다. 로고색을 어둡게 내린 텍스트용 단계를 만들지 않는다.

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| 흰 배경 위 `point-400` 텍스트 | 2.78:1 | 실패 |
| `point-400` 채움 위 흰 텍스트 | 2.78:1 | 실패. Primary에만 허용, 4절 |
| `point-400` 채움 위 `gray-900` 텍스트 | **6.38:1** | AA |

## 3. 역할 배치

| 역할 | 토큰 | 값 |
| --- | --- | --- |
| 아이덴티티: 로고, 액티브 아이콘, 포커스 링, 퍼널 막대 | `--accent` | `point-400` |
| 신호 마크: 점, 테두리, 아이콘 | `--attention-mark` | `point-400` |
| 신호 채움: 큐 칩, 확인 버튼, PROD 배지 | `--attention-solid` | `point-400` |
| 신호 채움 위 글자 | `--attention-on-solid` | `gray-900` |
| 신호 옆 글자 | `--attention-fg` | `gray-900` |
| Primary 액션 | `--action-primary-bg` | `point-400`, 글자는 흰색 |

- 유채색은 `#FD6C6E` 하나다. 성공·경고·정보용 초록, 노랑, 파랑과 별도의 빨강을 두지 않는다. 나머지 위계는 회색 명암으로 세운다.
- 아이덴티티는 늘 같은 자리에 있는 얇은 요소에만 쓴다. 경고는 평소 회색이던 요소가 코랄로 바뀌는 것으로 표시한다. 예를 들어 미처리 신고 칩은 0이면 회색, 1 이상이면 코랄 채움이다.
- 색만으로 상태를 말하지 않는다. 상태 배지는 점 옆에 글자를, 큐 카드는 아이콘·라벨·숫자를 함께 둔다.

### 검증된 조합

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| 로고색 채움 + `gray-900` 텍스트 | 6.38:1 | AA |
| 틴트(`point-50`) 위 `gray-900` | 16.22:1 | AAA |
| 본문 텍스트 on 캔버스 | 16.98:1 | AAA |
| 보조 텍스트 on 카드 | 7.56:1 | AAA |
| 흐린 텍스트 on 카드 | 5.57:1 | AA |
| Primary 로고색 채움 + 흰 텍스트 | 2.78:1 | 실패. 4절의 예외 |

## 4. Primary와 Danger

- Primary는 로고색 채움에 흰 글자다. 2절 규칙의 유일한 예외이며, 이 조합을 다른 자리에 복사하지 않는다. 확인 다이얼로그의 파괴적 실행 버튼도 같은 채움을 쓴다.
- Danger는 코랄 테두리에 잉크 글자인 아웃라인이다. 아웃라인 버튼은 글자를 물들이지 않는다.
- 코랄 채움은 Primary 버튼, 확인 다이얼로그의 최종 실행 버튼, 큐 칩에만 쓴다.

## 5. 차트 색

- 계열 토큰은 로고색인 `--chart-1` 하나다. 계열이 둘이면 주인공이 로고색, 나머지가 회색이다.
- 조각이 여럿인 도넛은 가장 큰 조각을 로고색, 나머지를 회색 `400`, `200`, `600` 순으로 칠한다. 조각은 넷을 넘기지 않으며, 더 많으면 순위 막대로 그린다.
- 셋 이상의 계열을 한 그림에 겹쳐야 하면 색을 늘리지 않고 그림을 나눈다.
- 로고색 선은 굵기 2px이다. 캔버스 대비가 2.66:1이므로 범례 이름, 아래 면, 툴팁을 함께 둔다.
- 계열 순서를 고정한다. 순환시키거나 필터 결과에 따라 다시 칠하지 않는다.
- 상태 색과 외부 브랜드 색을 차트 계열로 쓰지 않는다. 소셜 제공자도 카카오 노랑, 네이버 초록을 쓰지 않는다.

## 6. 타이포그래피

| 용도 | 폰트 |
| --- | --- |
| 본문, UI | Pretendard Variable |
| 숫자, ID, joinCode, 로그, JSON | JetBrains Mono |

본문 기본은 13px이다. 전역으로 `tabular-nums`를 켠다.

### 역할별 조합

이 표 밖의 조합을 새로 만들지 않는다.

| 역할 | 클래스 | 쓰는 곳 |
| --- | --- | --- |
| 페이지 제목 | `text-xl font-semibold tracking-tight` | `PageHeader` |
| 그룹 제목 | `text-base font-semibold tracking-tight` | `Card`, `Section`, `ConfirmDialog` |
| 본문 | `text-sm` | 표 셀, 문단 |
| 보조 | `text-xs text-ink-secondary` | 라벨, 설명 |
| 미세 | `text-2xs text-ink-muted` | 배지, 표 헤더, 힌트 |
| 지표 숫자 | `text-xl font-bold leading-none tracking-metric` | `Tile`, `ActionQueueStrip`, 목록 줄, 도넛 가운데 |

- 숫자 크기는 20px 하나뿐이다. 값이 길어도 한 칸만 줄이지 않는다.
- 굵기는 `medium`(라벨), `semibold`(제목), `bold`(숫자) 셋뿐이다.
- `tracking-metric`은 `--metric-tracking`(-0.02em)에서 온다. 화면에서 `tracking-[-0.02em]`을 직접 적지 않는다.
- `Section`과 `Card`의 제목은 같은 단계다.

## 7. 가로폭

- 본문 최대폭은 1320px이고 `AdminLayout`의 `<main>`에서만 정한다. 화면마다 `max-w`를 적지 않는다.
- 예외는 페이지 폭이 아니라 안쪽 요소에 건다. 지금은 패치노트 편집 영역 1100px 하나다.
- 표는 폭을 제한하지 않는다. 열이 많으면 카드 안에서 가로 스크롤한다.
- 나란히 놓을 카드가 있으면 폭을 줄이지 않고 나란히 놓는다.

## 8. 카드와 바닥

| 항목 | 값 |
| --- | --- |
| 캔버스 | 흰색 |
| 카드 그림자 `--shadow-card` | `0 1px 2px /0.05`, `0 3px 8px /0.045`, `0 16px 32px /0.06` 세 겹 |
| 카드 경계선 | `gray-200` |
| 카드 머리 구분선 | 없음 |
| 카드 본문 여백 | `px-5 pb-5`. 표는 `CardBody`가 아니라 카드 직속에 둔다 |
| `--bg-subtle` | `gray-100`. 배지, 눌린 자리, 표 행과 처리 대기 줄의 호버 |
| `--text-muted` | `#5B697F`. 스케일 밖 값 |

호버는 `bg-canvas`가 아니라 `bg-subtle`을 쓴다. 바닥이 흰색이라 `bg-canvas`는 카드 위에서 보이지 않는다.

## 9. 사이드 레일

레일은 화면 가장자리에서 떨어진 패널이고 카드와 같은 그림자를 쓴다.

- `--rail-width` 224px, `--rail-inset` 12px, `--rail-offset` 248px(본문이 밀리는 거리)
- 레일 머리에 구분선을 두지 않는다.
- 상단 바가 없다. 환경 배지는 레일 머리에 있고, 첫 위젯이 화면 맨 위에서 시작한다.

## 10. 격자

좌우 분할 비율은 둘뿐이다. 같은 급의 질문이면 반반, 본문과 곁들이면 넓은 쪽 2와 좁은 쪽 1이다. 세 번째 비율을 만들지 않는다.

## 11. 위젯 프리미티브

아래 표에 있는 것은 새 화면에서 다시 짜지 않는다.

| 프리미티브 | 쓰는 곳 | 고정된 것 |
| --- | --- | --- |
| `Tile` | 성격이 다른 지표를 나란히 놓는 칸 | 라벨 12px medium, 값 20px bold `-0.02em`, 보조 문구 12px, 아이콘은 라벨 오른쪽 끝에 흐리게 |
| `MetricRow` | 카드 안 목록의 지표 한 줄 | 값 오른쪽 정렬, 숫자 칸 고정폭, 값 뒤에 단위만 |
| `ActionQueueStrip` | 홈의 처리 대기 줄 | 판 하나에 세로 다섯 줄, 이름 아래 막대, 기준은 다섯 중 최대값, 색은 격리 메시지에만 |
| `ContextPanel` | 목록 옆에서 여는 상세 | 폭 420 과 720 둘뿐, 높이는 내용이 정함, 모달 아님 |
| `DataTable` | 모든 목록 | 선택 행은 코랄 틴트, 호버는 회색, 위아래 화살표로 행 이동, 실패와 빈 상태를 머리글 아래에 그림 |
| `lib/labels.ts` | 서버 enum 을 화면 말로 | 모르는 값은 원문 그대로 내보냄 |
| `TileGrid` `TileSkeletons` | 타일 줄 | `gap-3`, 좁은 화면 2칸. 칸 수는 3, 4, 5만 |
| `Meter` | 퍼널, 순위 막대 | 트랙 색, 반경, 0이면 그리지 않음, 0이 아니면 최소 2% |
| `TimelineDot` | 퍼널 단계 | 점 8px, 잇는 선 1px, 마지막에서 끊기 |
| `Legend` `Swatch` | 차트 범례 | 막대 계열은 네모, 선 계열은 선 |
| `charts/theme.ts` | 모든 recharts 차트 | 툴팁 상자, 축, 격자, 활성 점. recharts 를 import 하지 않는다 |

## 12. 그래프 형태

| 자리 | 형태 | 조건 |
| --- | --- | --- |
| 일자별 추이 | 위아래 두 판. 위는 막대(방 생성과 완주), 아래는 선(참여자) | 두 판 사이에 실선을 긋고 아래 판에 이름을 붙인다 |
| 지표 옆 흐름 | 스파크라인 | 축과 눈금 없음 |
| 방 진행 퍼널 | 가로 막대 + 직전 단계 자국 | |
| 구간 분포: 방 인원, 플레이 횟수, 소요 시간, 신뢰도, 처리 시간 | 히스토그램. 세로 기둥을 붙여 세운다 | 순서가 있는 수치 구간 |
| 순위와 구성 목록: 게임별, 조치 종류, 담당자, 진행 단계, 검열 판정 | 가로 막대 `DistributionBars` | 이름이 길거나 항목이 다섯을 넘는다. 순위 숫자는 `ranked`로 켠다 |
| 구성비: 소셜 제공자, 신고 카테고리 | 도넛 | 합이 하나의 전체이고 항목이 넷 이하이며 순서가 없다 |
| 평가 통과율 추이 | 선 | 세로축을 0~100%로 고정 |
| 일자별 한 계열: 가입 | 꺾은선 + 옅은 면 | 곡선을 쓰지 않는다 |
| 일자별 두 계열: 접수와 처리, 걸림과 통과, 성공과 실패 | 나란한 막대 | 쌓지 않는다 |

- 이중 축은 쓰지 않는다. 자릿수가 다른 계열은 판을 나눈다.
- 가로 막대는 `DistributionBars` 하나만 쓴다.
- 도넛에서 로고색은 한 조각만 쓰고, 이름·값·비율을 범례에 적는다.
- 형태는 위 표의 조건으로만 고른다. 막대만 넷을 늘어놓지 않는다.
- 구간 경계와 칸을 더해 나오는 요약 수는 서버가 정해 내려보낸다. 화면이 라벨로 칸을 찾아 더하지 않는다. 소요 시간 경계는 5분, 10분, 20분, 30분이다.
- 차트는 카드 높이를 채운다. 카드에 `flex flex-col`, 본문에 `flex-1`을 준다.
- recharts 차트는 바깥 칸 `relative flex-1`, 안쪽 칸 `absolute inset-0`으로 감싼다. 그러지 않으면 `ResponsiveContainer`의 `height="100%"`가 0으로 풀려 빈 카드가 된다. 히스토그램은 recharts를 쓰지 않는다.

## 13. 컴포넌트는 역할 별칭만 참조한다

`--point-400` 같은 팔레트 토큰을 직접 쓰지 않고 `--accent`, `--attention-mark` 같은 역할 별칭을 쓴다. 별칭의 뜻을 바꾸면 그 별칭을 쓰는 자리를 다시 확인한다.

## 14. 알려진 제약

- `character.svg`는 SVG 안에 1000x1000 PNG가 base64로 들어 있다(약 100KB). 1000px을 넘겨 확대하면 깨지고 `currentColor`로 색을 바꿀 수 없다. 파비콘(32px), 레일 아바타(24~32px), 로그인 화면(약 120px)에만 쓴다.
- 다크 모드는 구현하지 않는다.
