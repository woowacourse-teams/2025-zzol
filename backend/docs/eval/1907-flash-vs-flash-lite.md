# flash-lite 와 최신 flash 의 닉네임 검열 판정 비교 (#1907)

- 측정일: 2026-11-11
- 질문: 무료 한도 때문에 `gemini-3.5-flash-lite` 를 골랐는데([ADR-0038](../adr/0038-nickname-audit-gemini-call-conditions.md)), 그 대가로 판정 품질을 잃었나?

## 결론

**골든셋 579건에서는 flash-lite 가 최신 flash 보다 나쁘다는 근거가 없다. 다만 이 세트는 두 모델 모두 천장에 닿아서, 작은 차이가 없다고 말할 근거도 되지 못한다.**

- **욕설과 우회 재현율은 두 모델이 같다.** 둘 다 235건을 모두 걸러냈다. 미탐 0건의 95% 신뢰 상한은 3의 법칙으로 1.3%(3/235)다.
- **정상 닉네임 오탐은 flash-lite 0건(0/301, 상한 1.0%), flash 1건(1/301)이다.** flash 의 1건은 `아저씨발냄새`이고 3회 판정이 FLAGGED, PENDING, CLEAN 으로 모두 달랐다.
- **정답 맞음/틀림을 짝지은 McNemar 정확 검정은 b=0, c=1, p=1.000 이다.** flash 만 맞은 닉네임은 없고 flash-lite 만 맞은 닉네임이 1건이다.
- **미리 정한 비열등 한계 -2%p 안에 들어온다.** 정답률 차이는 +0.17%p 이고 95% 구간은 -0.17%p 에서 +0.51%p 다. 엇갈린 표본이 1건뿐이라 이 구간은 근사값으로만 읽는다.
- **두 모델의 판정 차이는 반복 흔들림보다 조금 크고, 그 차이는 경계 닉네임에 몰려 있다.** 회차 쌍의 판정 불일치율은 같은 모델끼리 0.86%(flash)와 1.19%(flash-lite), 두 모델 사이 1.70% 다. 다수결이 엇갈린 9건 중 8건이 경계(AMBIGUOUS) 표본이다. flash 는 경계 43건 중 22건을, flash-lite 는 14건을 FLAGGED 로 차단했다. 사람 확인(PENDING)으로 보낸 건은 두 모델 모두 0건이라 어느 쪽도 정답이 아니다(#1911).
- **최신 flash 는 운영 조건에서 돌지 못했다.** 배치 250건과 타임아웃 120초로는 호출 9회 중 4회가 타임아웃으로 실패했다. 타임아웃을 300초로 늘려 다시 쟀을 때 응답은 평균 72.4초, 최대 200.6초였다. flash-lite 는 평균 17.4초, 최대 28.3초다.

판정 품질이 같고 응답이 4배 빠르므로 flash-lite 선택을 뒤집을 이유는 이 측정에서 나오지 않았다. 품질 차이가 있는지는 더 어려운 표본으로 다시 봐야 한다. 하드 골든셋 350건 측정은 [하드 골든셋](#하드-골든셋-측정-전) 절에 계획만 적었다.

### 지표 정의

- **다수결**: 닉네임마다 판정을 받은 회차의 최빈값이다. 동률이면 앞선 회차 판정을 쓴다.
- **재현율**: 욕설(PROFANE)과 우회(EVASION)를 FLAGGED 나 PENDING 으로 걸러낸 비율이다.
- **정답**: 욕설과 우회는 FLAGGED 나 PENDING, 경계는 PENDING, 정상은 CLEAN 이면 맞은 것으로 센다.
- **3의 법칙**: n 건에서 0건이 나왔을 때 실제 비율의 95% 신뢰 상한을 3/n 으로 잡는다.
- **비열등 한계**: 정답률 차이 -2%p. 579건에서 12건쯤이다. 측정 전에 분석 스크립트에 고정한 값이고, 운영 근거가 있는 숫자는 아니다.

## 한계

- **천장 효과.** 두 모델 모두 욕설과 우회를 100% 걸러냈다. 이 세트로는 재현율 차이가 1.3%p 아래인지까지만 말할 수 있고, 어느 모델이 어려운 우회를 더 잘 잡는지는 알 수 없다.
- **골든셋 분포는 운영 분포가 아니다.** 579건 중 욕설과 우회가 235건(40.6%)이다. 운영 닉네임은 대부분 정상이라 오탐 한 건의 무게가 여기보다 크다. 정상 301건에서 오탐 0건이면 상한이 1.0%인데, 하루 닉네임이 수백 건을 넘으면 이 상한으로는 오탐이 없다고 장담하지 못한다.
- **경계 43건은 품질 비교에 쓰지 못했다.** 정답이 PENDING 인데 두 모델 모두 PENDING 을 0건 냈다. 경계 표본에서 두 모델이 갈린 8건은 어느 쪽이 낫다고 할 수 없다.
- **반복이 3회뿐이고 flash-lite 앞쪽 250건은 2회다.** 2회 판정이 갈리면 첫 회차 판정을 다수결로 썼다. 그렇게 정한 닉네임은 경계 표본 `병신년` 1건이고, 두 판정 모두 PENDING 이 아니라서 정답 집계는 바뀌지 않는다.
- **flash 는 운영과 다른 타임아웃으로 쟀다.** 판정 비교는 300초 측정을 썼다. 운영 타임아웃 120초에서는 flash 호출 18회 중 5회가 120초를 넘겼다(120초 측정 실패 4회, 300초 측정에서 200.6초 1회).
- **하루치 측정이다.** 응답 시간과 503 은 측정 시각의 서버 부하를 탄다. 모델 버전이 바뀌면 판정도 달라질 수 있다.
- **정답률 차이 구간은 Wald 근사다.** 엇갈린 표본이 1건이라 구간 폭을 그대로 믿기 어렵다. 결론은 b=0 이라는 건수에 기댄다.

## 하드 골든셋 (측정 전)

`golden-hard.csv` 350건(우회 134, 정상 106, 경계 74, 욕설 36)은 이 브랜치에 합쳐 두었고 아직 재지 않았다. 측정일의 Gemini 할당량 때문에 다음 날로 미뤘다.

- 같은 조건(배치 250, 3회 반복, 두 모델)이면 호출이 12회 든다. 한 회차가 호출 2회다.
- flash 는 타임아웃 300초로 잰다. 120초로는 579건 측정에서 호출 9회 중 4회가 실패했다.
- 분석 스크립트가 카테고리별 표를 내므로 하드네거티브 오탐과 혐오차별, 집단비하 축을 그 표에서 본다.
- 하드셋 라벨은 언어 모델 두 번으로 달았다. 두 라벨의 κ 는 0.920 이고 혐오차별과 집단비하 축의 일치율은 73.1% 다. 이 두 축의 재현율은 라벨이 틀렸을 가능성을 함께 놓고 읽어야 한다.

## 재현 방법

행 단위 판정은 `data/` 에 있다. 열은 닉네임, expected, 카테고리, 회차, 배치, 판정, 배치 응답 시간(ms), 모델이 쓴 사유다.

```bash
cd backend
python3 profanity/scripts/compare_models.py \
  gemini-3.8-flash docs/eval/data/1907-golden-gemini-3.8-flash-timeout300.tsv \
  gemini-3.5-flash-lite docs/eval/data/1907-golden-gemini-3.5-flash-lite.tsv
```

다시 재려면 모델마다 러너를 돌린다. TSV 는 `profanity/build/reports/golden/` 에 남는다.

```bash
cd backend
GEMINI_API_KEY=... NICKNAME_AUDIT_MODEL=gemini-3.8-flash NICKNAME_AUDIT_BATCH_SIZE=250 \
  NICKNAME_AUDIT_REPEATS=3 NICKNAME_AUDIT_HTTP_ATTEMPTS=1 NICKNAME_AUDIT_TIMEOUT_SECONDS=300 \
  ./gradlew :profanity:goldenTest
```
